# WD-72 — The upgraded popup keeps Open All Tabs and every shipped setting

**Epic:** EP-09 · **Wave:** 3 · **Priority:** P0

## Overview

A no-regression ticket. The popup has been changed by WD-42 (account card),
WD-54 (watch sync), WD-59 / WD-60 / WD-110 (sync line) and WD-73 (one status
area). This ticket checks, control by control, that nothing the shipped
extension's popup did was taken away, with no account connected and with one
connected, and leaves tests behind that fail when something is.

**No regression was found, so no shipped file changes in this ticket.** The
deliverable is the tests and the checklist below.

The reference is the shipped extension (a local copy of the Web Store
version, the same code as commit `45c1419`) and the baseline written from it
(`docs/extension-baseline.md` in the WatchDesk repository, §5, §7, §8).

## Acceptance criteria

- [x] Open All Tabs opens one tab per enabled watch exactly as the current
      shipped extension does.
      — `openRequiredTabs`, `openOrFocusWatchTab` and `findExistingSearchTab`
      in `popup.js` are byte-for-byte the shipped ones, and none reads a
      watch's id: they use `enabled`, `siteId` and `url`, so WatchDesk's ids
      (WD-54) do not reach them. `tests/popup-parity-open-tabs.test.js` (40
      tests) drives the real button in both modes: one background tab per
      enabled tab-only watch in list order, none for a paused or
      background-checked watch, reuse of an exact or drifted tab, two watches
      on one site, the ambiguous case, two watches on one search, the
      `window.open` fallback, the status text. "opens exactly the tabs it
      opened before the account was connected" compares the two modes
      directly. The 18 unconnected tests pass unchanged against the shipped
      copy. In Edge: 3 tabs opened, "3 already open." on the second click, a
      drifted LinkedIn tab reused, the same 3 tabs with server ids, and no
      tab for a watch paused on WatchDesk.
- [x] Every setting present in the current popup (sound, mute, interval,
      keyword filter) is reachable in the upgraded popup, even before Wave
      4's full sync (US-039) lands.
      — All 48 elements the shipped `popup.html` gives an id are still there,
      same element, same order (`tests/popup-parity-markup.test.js`), and
      `tests/popup-parity-settings.test.js` (86 tests) uses each setting in
      both modes: it sends the shipped message, the value lands in
      `chrome.storage.sync`, it is shown again on reopening, and it has its
      effect (the alarm is re-armed, a muted check raises no notification or
      tone, the keyword filter decides what reaches the feed). Settings stay
      local: "no setting is ever in a request to WatchDesk". In Edge: all
      four visible and working before and after connecting.

## Decisions taken

The handoff said to proceed without stopping. Each of these is open to
challenge at review.

1. **The tests run the real `popup.js` against the real `background.js`.**
   A new helper, `tests/helpers/popup-harness.js`, loads `popup.html` in
   jsdom, imports `popup.js` and `background.js`, and joins them with the
   mocked `chrome.*` and the fake WatchDesk. A test clicks a control and
   checks both the message and the storage write. Mocking the worker would
   have checked the message only.
2. **"Connected" means the upgrade path:** the same five watches, uploaded
   by the first sync, now under WatchDesk's ids. That is the case the ticket
   is about.
3. **`POPUP_PARITY_ROOT` points the harness at another copy of the
   extension.** With it set to the shipped copy, the unconnected tests run
   against shipped code unchanged (connected tests are skipped). This is how
   "same as shipped" was checked rather than asserted. It is three lines in
   the helper and is unset in CI.
4. **No shipped file was edited.** No regression was found, and WD-71 and
   WD-73 were editing the popup in parallel. `tests/helpers/chrome-mock.js`
   and `fake-watchdesk.js` are not edited either; the harness adds what it
   needs on top of them.
5. **The markup test lists the shipped ids in the test file.** CI cannot
   read the shipped copy, so the 48 ids (element and order) are written
   down. Adding to `popup.html` passes; removing, renaming or reordering a
   shipped control fails.
6. **The parity tests do not assert the sync line's wording.** That belongs
   to `popup-watch-sync.js` and its own tests; WD-73 changed it while this
   ticket was open.

## Known limitations

- The harness approximates three things, stated in its header: a message is
  routed by its type because one `chrome` object serves both sides;
  `chrome.tabs.query({ url })` is a glob over the URL; closing a popup clears
  all pending timers. The Edge walkthrough covers the real versions of the
  first two.
- jsdom applies no CSS, so "reachable" is checked as "in the page, not
  hidden, in the panel the gear opens", plus the two CSS rules that show and
  hide the panel. Visibility itself was checked in Edge.

## Found outside this ticket's scope

Not changed here; for the main session to file if wanted.

1. **`getSettings()` writes `watches` directly, also when connected.**
   `migrateWatchUrls` re-normalises each LinkedIn URL on every read and
   writes the list back if one changed (`background.js`, `getSettings`).
   Connected, that is a write to the copy outside `watch-sync.js`. It only
   happens when WatchDesk stored a URL the extension normalises differently;
   the two rules are the same today.
2. **Import while WatchDesk is unreachable** replaces the copy with the
   file's watches and the following sync fails, so the list shown is the
   file's until the next successful sync (WD-54, decision 15, read from the
   code, not reproduced).
3. **The Reset hint in Settings is fixed text**: "Clears every watch, the
   feed, and all settings back to defaults." Connected, the watches are kept
   and only the confirm dialog says so.
4. **The settings controls do not update the popup's cached state**, in the
   shipped popup as well: after changing mute, interval or sound, a local
   re-render (clicking a watch's Edit, for example) shows the old value
   until the popup is reopened. The stored value is right. Read from the
   code, not reproduced; shipped behaviour, left alone.
5. **The install handler writes the settings back** (`onInstalled`:
   `getSettings()` then `saveSettings()`), so anything written to
   `chrome.storage.sync` in the first moments after install can be
   overwritten with the defaults. Shipped behaviour; it only showed up as a
   race in the walkthrough's own setup.

## Testing notes

`npm run lint` is clean (`check-syntax` parses 15 of 15 files) and
`npm test` passes **885 tests in 15 files, 8 skipped** (the 8 are the tests
that apply to one mode only, skipped in the other). 291 of them are new: 283
run, 8 skipped.

**Against the shipped copy.** `POPUP_PARITY_ROOT=<shipped copy> npx vitest
run tests/popup-parity`: 165 passed, 12 skipped (the connected-only tests).
The unconnected tests therefore describe what the shipped extension does,
not what this branch happens to do.

**Mutation check.** 40 deliberate breaks, one at a time, in `popup.js`,
`popup.html`, `background.js` and `watch-sync.js`; each failed at least one
parity test. Among them: tabs for paused watches, a tab for a background
site, the batch forgetting claimed tabs, opening a tab when ambiguous, the
interval sent as text, mute inverted, the filter toggle dropping the
keywords, the workplace filter hiding untyped postings, the Test button
removed, a sync that resets settings.

**In a real browser: 35 of 35 checks passed.** Microsoft Edge via
Playwright, loading an unpacked copy of this branch whose development origin
pointed at a local stub of the watch, device and ingest routes; the four job
sites were answered locally. The committed `config.js` stays on production.

- Not connected: every main-page control and every Settings control
  visible; interval, sound, mute and a keyword stored in
  `chrome.storage.sync`; Open All Tabs "opened 3 tabs." (Glassdoor,
  LinkedIn, Upwork, in the background), then "3 already open.", also after
  the LinkedIn tab's URL had drifted; zero requests to WatchDesk.
- Token stored: the five watches uploaded and under server ids; the
  settings chosen before connecting still shown; changing all four stores
  them locally and no request carries a setting; Open All Tabs opens the
  same three tabs; a watch paused at the stub gets no tab. No page errors;
  the token never in the popup's DOM.

**Not verified:** the real WatchDesk app or its production origin (a stub
stood in; pairing was skipped by storing a stub token); Google Chrome itself
(Edge was used); the real toolbar popup (opened as a tab so it stays open);
the real job sites (answered locally, so their own URL rewriting and sign-in
walls were not exercised); the tone actually being audible; Export's file
dialog and Import's file picker in a browser (unit-tested only).

## Manual verification (Chrome)

1. Load the repository root unpacked. Add a Glassdoor, a LinkedIn and an
   Upwork watch; pause one.
2. Click **Open all tabs my watches need ↗**: one tab per active watch, in
   the background; the footer says "opened N tabs.". Click again: "N already
   open."
3. Change the interval and the sound, press **Test**, open ⚙ and tick
   **Mute**, add and remove a keyword. Reopen the popup: all as left.
4. Connect an account and repeat steps 2 and 3: the same tabs, the same
   settings.

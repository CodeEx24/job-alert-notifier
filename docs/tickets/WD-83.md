# WD-83 — A confirmation after the import, and nothing removed before it

**Epic:** EP-11 · **Wave:** 4 · **Priority:** P2

## Overview

As a user who just imported, I want a confirmation screen showing how many
watches/listings were imported per platform, so I can trust the migration
actually worked before I stop relying on the old local data.

WD-81 built the import and ended it with one sentence; WD-82 counted what
was added apart from what the account already had, in all and by site, and
left the screen to this ticket. This ticket:

1. turns the end of the import into a **report**: a table by site, the
   reasons behind every "left out", the applied marks and the settings;
2. keeps the report until the user is done with it ("Close" puts it away,
   Settings brings it back);
3. decides what "local data is left in place until the user confirms" can
   honestly mean for an extension that goes on working from that data, and
   builds exactly that: **Remove the earlier copies…**, in two steps.

```
YOUR DATA WAS IMPORTED, WITH SOME LEFT OUT
3 watches uploaded, 1 watch was already in your account, 5 listings
uploaded, 1 listing was already in your account, 1 marked applied, your
settings saved.

What was imported, by site
                     Watches                    Listings
Site           Added  Already in  Left   Added  Already in  Left
                      your account out          your account out
LinkedIn         1        0        1       2        0        1
Glassdoor        1        0        0       1        0        1
Upwork           1        0        0       1        0        1
OnlineJobs.ph    0        1        0       1        1        1
Total            3        1        1       5        1        4

 • LinkedIn: WatchDesk didn't accept 1 watch. It stays in this browser.
 • LinkedIn: 1 listing left out, because its watch isn't in your account.
 • …
 • Nothing was removed from this browser. Its feed still has all 10 listings.
 • It also keeps a copy of your settings (the check interval and the alert
   sound) from before it was connected, inside this extension and in this
   browser only. The copy stays until you remove it below.
 • If the import looks wrong, you can leave everything as it is, or import
   again: what your account already has is not added twice. The extension
   can't undo an import or delete anything from your account; that is done
   on WatchDesk.
[ Close ]  [ Import again… ]  [ Remove the earlier copies… ]
```

One pull request, this repository only. No web change, no new endpoint, no
manifest change.

## Acceptance criteria

- [x] Per-platform import counts are shown after the batch completes.
      — The card's end state is a table (`describeReport()` in
      `popup-local-import.js`): LinkedIn, Glassdoor, Upwork and
      OnlineJobs.ph, always all four, plus "Other sites" when the counts
      have it; for each, watches and listings **added**, **already in your
      account** and **left out**; a totals row that is the sum of the rows
      and equals the counts the import recorded. Each "left out" has a line
      saying why, by site. Then the applied marks (carried, not carried)
      and the settings (imported, none to import, refused with the reason).
      Watches were not counted by site before; `counts.watchesBySite` is
      new. Tests (`tests/import-confirmation.test.js`): "shows, for each of
      the four sites…", "totals that are the sums of the rows, and the
      counts the import recorded", "is a real table…", the four
      `describeReport` tests. Real browser: Testing notes.
- [x] Local chrome.storage data is left in place (not cleared) until the
      user explicitly confirms, so nothing is destroyed if the import looked
      wrong.
      — The import removes nothing (as before; now also tested as such),
      and neither does closing the report, a check, an alarm, time, a
      restarted worker, a disconnection or another import. The one thing
      that removes anything is `confirmImport()`, reached by the popup's
      **second** click, and it removes only the copies listed under "What
      Confirm clears". **Most of what is in `chrome.storage` is never
      cleared, confirmed or not**: it is what the extension works from (the
      inventory below). Tests: the "nothing in this browser is removed
      until the user confirms" block, "Remove the copies: exactly the
      copies this import put into the account", "a copy that holds anything
      the account did not get is kept", "only the finished import of the
      account that is connected".

## The inventory: every storage key, and what Confirm does to it

"Working state" is what a connected extension needs to go on doing its job;
clearing it would re-announce old postings, blank the popup or break the
sync. "Leftover" is a copy that exists only because of how the browser was
before it worked with the account.

| `intervalMinutes`, `soundId`, `notificationsMuted`, `titleFilter` | The settings the check cycle reads; connected, the last-synced copy of the account's (WD-79) | Working state | Untouched |

### `chrome.storage.session`

| Key | What it is for | Kind | Confirm |
|---|---|---|---|
| `watchdeskPairing`, `watchdeskPairingOutcome` | A pairing in progress and how the last one ended (WD-42) | Working state | Untouched |

**Nothing else is safe and useful to clear, so nothing else is.** In
particular not the feed and not `seenIds`: the feed is what the popup shows
and the only place the listings an import left out still are, and without
`seenIds` the next check would announce every posting on the page as new.
`tests/import-confirmation.test.js` ("leaves every key the extension works
from byte for byte as it was, and the next check announces nothing twice")
lists the keys a connected browser holds after an import and a check,
compares every one of them before and after Confirm as serialised bytes,
and then runs two checks: the same page announces nothing, a new posting is
still announced.

### What Confirm clears, exactly

| The import | `watchdeskSettingsBeforeConnect` | `watchdeskWatchesBeforeConnect` | `watchdeskImport` |
|---|---|---|---|
| "Import" at the first question | Removed (it is what the import saved) | There is none of this import's; one that exists is from an earlier "Not now" under another account and is **kept** | Removed |
| "Not now", then "Import" from Settings | Removed | Removed (the import uploaded those watches) | Removed |
| Either, with a setting WatchDesk refused | **Kept**: it is the only copy of that setting | as above | Removed |
| The second, with a watch WatchDesk refused | as above | **Kept** | Removed |
| The copy is not the one the import read (changed since) | **Kept** | **Kept** | Removed |
| A record finished before this version (names no copy as its own) | **Kept** | **Kept** | Removed |

The rule in one line: **a copy is removed only when this import put all of
it into the account.** How that is known: the finished record keeps the
settings the import saved (`settings`) and when the set-aside watches it
uploaded were set aside (`ownTakenAt`); a copy that does not match, or an
import with something refused, leaves the copy where it is. The popup says
which it will be before the click ("Its copy of … is kept: this import did
not put all of it into your account."), and when there is nothing but the
report to remove the button says "Remove this report…".

## The screens

| State | What the card shows | Buttons |
|---|---|---|
| The import ended | The summary sentence, the table, the lines above | Close · Import again… · Remove the earlier copies… |
| It ended with something left out | The same, titled "…, with some left out", in the warning colour | the same |
| It stopped part of the way | "The import has stopped for now", **the table of what got in so far** ("Imported so far, by site"), "The import is not finished…" | Retry now, and nothing else |
| Closed | Nothing. Settings → **Show what the import did…** brings it back | — |
| "Remove the earlier copies…" pressed | "Remove the earlier copies from this browser?", what goes, what stays, "This can't be undone." | **Keep them** (has the focus) · Remove the copies |
| Removed | "The earlier copies were removed", what was removed | Close |
| "Import again…" pressed | WD-81's second question, worded for a second import | Import · Not now (back to the report) |
| No account, or another account | Nothing; no button; `local-import-confirm` does nothing | — |

## Decisions taken

The handoff said to proceed without stopping. Each is the option I would
have recommended and is open to challenge at review.

1. **"Local data" that Confirm clears is the two pre-connection copies and
   the report, nothing else.** The inventory above is the argument. The
   ticket's wording imagines a migration after which the local data is
   redundant; it is not, the extension keeps working from it.
2. **A copy is removed only when the import put all of it into the
   account.** With a setting or a watch refused, the copy is the only place
   that value still is, so it is kept and the card says so. Narrower than
   the handoff allowed ("may clear … the snapshots"), on purpose.
3. **The copies carry no owner, so ownership is decided by what the import
   read**, not by who is connected: a watch copy from another account's "Not
   now" was never uploaded by this import and is never removed by it. This
   is what "never clear account A's safety copies while connected as B"
   comes to in code.
4. **Two steps, both in the card.** The removal cannot be undone and its
   button sits beside "Close"; the first step sends nothing and only says
   what would go. Not `confirm()`: the popup has no modal for this card
   (WD-81, decision 14), a native dialog's default button is OK, and it
   cannot say which copies are kept. The second step is the popup's own
   state, not stored: a popup opened again starts from the report.
5. **The focus is never handed to a button that removes.** The buttons are
   ordered Close, Import again, Remove…, then Keep them, Remove the copies;
   the card's focus rule takes the first one on show.
6. **"Close" no longer removes the record** (WD-81 removed it). It sets
   `closed`; Settings shows the report again. Otherwise the report could
   not be found again and the copies could never be confirmed away.
7. **After Confirm the report is gone too.** Nothing reads a finished
   record, and "this report" is named in what is removed. The account's
   answer (`watchdeskImportAnswers`) stays, so the offer does not come back.
8. **One table, six number columns, two header rows** (Watches / Listings ×
   Added / Already in your account / Left out), built with `caption`,
   `scope` and `headers` on every cell. The popup is 560 px wide and the
   table fits (checked in a real browser). The reasons are lines under the
   table rather than four more columns.
9. **All four sites are always listed**, with zeros, so the table has the
   same shape every time; "Other sites" only when the counts have it.
10. **`counts.watchesBySite` is a new key beside `bySite`**, not new fields
    inside it: WD-82 defines `bySite` as the six listing counts that add up
    to the feed, and its tests say so.
11. **A record finished before this version still adds up**: what it holds
    in all but not by site (its watches) gets a row "Site not recorded".
12. **A stopped import shows the table of what got in so far**, labelled as
    such, with Retry and nothing else. A running import shows only its
    progress: its numbers change every 600 ms.
13. **"Import again" is WD-81's second question, not a new flow.** From a
    finished import the record becomes `offered-again` with the report kept
    in `back`; "Not now" restores it and does **not** record a "no" for the
    account; "Import" runs the import again, which by WD-82 can only add
    what the first one missed. While that question is open the account
    syncs as an account that said yes (`keepsOwnWatchesLocal()` is false
    with `back`), so a refused watch is not moved out of the list.
14. **No "undo on the server".** The extension has no route that deletes a
    listing; the card says so and points to WatchDesk.
15. **Confirm names the report it is for** (`finishedAt`) and is checked
    inside the queue a new token is stored in, so neither a second import
    nor a pairing can come between the user's reading and the removal.
16. **Reset Extension's confirm now also mentions set-aside watches while a
    finished import still keeps them** (it already cleared them).
17. **`watch-sync.js` gained `bySite` on a sync's outcome**; the matching
    rule (`watch-url.js`) is untouched.

## API changes

None towards WatchDesk. Worker ↔ popup:

| Message | Answer |
|---|---|
| `local-import-review` (new) | The popup state; the report is open again |
| `local-import-confirm` `{ finishedAt }` (new) | The popup state plus `localImportConfirmed`: `{ watches, settings }` removed, or `null` when nothing was done |
| `local-import-dismiss` | Unchanged in shape; the report is closed, not removed |
| `local-import-again` | Now also from a finished import |

`localImport` in the `done` phase is now `{ phase, closed, finishedAt,
counts, listingsHere, copies: { watches, watchesRemovable, settings,
settingsRemovable }, confirmable, redo }`; `counts` gains `watchesBySite`;
the `offered` phase gains `redo: true` when asked from a finished import.
Counts and names only: no token, no listing, no URL.

## Known limitations

- **A report does not survive a new pairing.** A disconnection keeps it
  (and shows nothing while disconnected), but pairing again, even with the
  same account, replaces the record as it always has. The copies then stay
  in this browser with no report to remove them from: the safe side, and
  Reset Extension still clears the watches copy.
- **The settings copy can come back.** After it is removed, a later
  connection's first sync keeps a copy again (of the settings the browser
  then holds), as WD-79 does for any browser without one.
- **Reset Extension does not clear the settings copy** (unchanged from
  WD-79 and WD-81); it clears the report and the watches copy.
- **The report is long** when much was left out: one line per site and
  reason, above the popup's watch list.
- **"Import again" sends the whole feed again**, because WatchDesk has no
  route that says what an account already has (WD-82, "What the API does
  not let the import do"); it adds nothing twice.
- **Counts carried over from WD-81/WD-82** are unchanged: a watch created
  just before a worker is stopped is counted as "already in your account"
  on the next try, by site too.
- **The row "Site not recorded"** appears only for an import finished
  before this version.

## Manual verification (Chrome)

1. Load the repository root unpacked, pointed at a local WatchDesk
   (`WATCHDESK_ENV = "development"`; do not commit that). Have a few watches
   on more than one site and a feed.
2. **Connect Account**, approve, **Import**. The card ends with the table:
   check the rows against WatchDesk's Watches and Listings pages, and that
   each column's total is the sum of its rows.
3. Close the popup and open it: the report is still there. **Close**, open
   ⚙: **Show what the import did…** brings it back.
4. Look at the feed: everything is still there.
5. **Remove the earlier copies…**: read what it says, press **Keep them**;
   nothing changed. Press it again and **Remove the copies**: the card says
   what was removed; the feed, the watch list and the settings are as they
   were, and the next check announces nothing old.
6. In a second profile, stop the WatchDesk server mid-import: the card says
   it stopped and shows what got in so far, with **Retry now** only.
